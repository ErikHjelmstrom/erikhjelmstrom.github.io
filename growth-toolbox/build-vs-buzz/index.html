      01 / THE PROTOTYPE

      Four states before one line of live logic.

      The low-fidelity prototype mapped the complete user journey before development: initial search, loading, complete results and partial failure.

      This made error handling and methodological transparency part of the product rather than additions at the end.

      View the paper prototype ↗

      02 / HOW IT WORKS

      Two sources.
      One transparent profile.

      1. 01

        Define equal periods

        The latest 30 days are compared with the preceding 30 days for both sources.

      2. 02

        Measure within each source

        GitHub repository counts are compared only with GitHub. Hacker News stories are compared only with Hacker News.

      3. 03

        Describe the direction

        The direction of both changes creates a descriptive signal profile without pretending the units are equivalent.

      03 / LIMITATIONS

      A signal, not a verdict.

      Repository creation and Hacker News stories do not measure revenue, adoption or customer demand. They are directional indicators of visible activity on two specific platforms.

      Search terms can also be ambiguous. Results should be treated as a starting point for further research, not proof that a market is growing.

      GitHub limits anonymous API requests. The app reports partial results rather than inventing missing values when one source is unavailable.
